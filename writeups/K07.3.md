**What you are about to read:** how a service that inspects packages becomes a service that
runs *your* package in the inspector's privileged context, so its restricted assessment —
normally returned only to the inspector — comes back to you.

## Objective

Use the framing capability to perform the inspector's protected package action and recover
its restricted assessment.

## Background you need

- **"Framing"** is the envelope around a package: declared interface, entry point, metadata
  telling the service *how* to invoke what you submitted. The service validates the frame,
  then executes the payload.
- **The inspector** is a privileged identity inside delivery. It may request a structured
  assessment of a package. That assessment is restricted: asking as your own identity
  returns an authorization error, not data.
- **Confused deputy:** a service that (a) accepts a caller-supplied description of work,
  (b) executes it with its own privileges, and (c) authorizes the outer request by caller
  identity while the inner action runs as the inspector.
- The range documents `POST /api/inspections` with `/{id}/trace` and `/{id}/envelope`, and a
  package upload taking `interface`, `source` and `expected_output`.

## Walkthrough

### 1. Recon — map the lifecycle

```bash
# illustrative: submit a minimal inspection and read the echoed envelope
curl -sS --socks5-hostname 127.0.0.1:1080 --cacert /home/kali/ctf/ca.crt \
  -H "Authorization: Bearer <delivery credential>" -H 'Content-Type: application/json' \
  -d '{"package":"<baseline connector package>"}' \
  https://delivery.keplerops.test:8443/api/inspections
```

The response carries an inspection id, an `envelope` describing how the package was
interpreted, and a `trace` of the checks. The envelope is the framing contract, derived from
*your* submission.

### 2. Finding the flaw — the frame decides the action

Compare two submissions differing only in framing (interface, entry point). If behaviour
changes — different checks, an "assessment" object, or a trace naming the inspector as the
acting principal — then the frame is an input to the authorization decision, not just to
execution. The giveaway is in `/api/inspections/{id}/trace`: the assessement is attributed
to the inspector while the request authenticated as you.

### 3. Exploitation — ask for the protected action from inside the frame

```bash
# illustrative: upload a crafted package with its declared interface
curl -sS --socks5-hostname 127.0.0.1:1080 --cacert /home/kali/ctf/ca.crt \
  -H "Authorization: Bearer <delivery credential>" \
  -F 'interface=fieldkest.connector/v3' -F 'source=@crafted.js' \
  -F 'expected_output=<shape you want back>' \
  https://delivery.keplerops.test:8443/api/diagnostics/<job>/package
```

Re-run the inspection and read `/{id}/envelope` and `/{id}/trace`: the assessment returned
is the inspector's, not yours.

### 4. Getting the flag

Solved by a team agent; no request/response was retained, so the flag is **accepted, value
not recorded**. The evidence-supported shape is: submit a crafted frame to
`POST /api/inspections`, then read the restricted assessment from envelope/trace.

## Why this works (the vulnerability explained)

The service performs two authorization decisions and implements one.

1. **Outer:** may this caller submit an inspection? Implemented and correct.
2. **Inner:** may this *action* (the protected assessment) be performed? Delegated to the
   inspector's service identity, which is always allowed — so the check always passes.

Any caller-controlled field that selects the inner action (interface name, entry point,
declared role, operation) becomes an authorization bypass primitive. Two details worsen it:
the frame is validated for *shape* rather than allow-listed for *meaning*, and the inner
action's result is returned to the caller, leaking the deputy's output directly.

## Detection and fix

- **Detect:** traces where acting principal ≠ requesting principal; submissions whose
  declared interface/operation does not match the caller's role; a rise in `assessment`
  objects returned to non-inspector accounts.
- **Fix:** authorize the *pair* (caller, inner action); pass the caller identity into the
  executor and check there, not only at the HTTP edge. Allow-list operations per caller, and
  make the inspector's assessment a separate, explicitly authorized endpoint.
- **Fix structurally:** run the executor with the caller's effective permissions (token
  exchange / consent-based impersonation), so "run as inspector" is not expressible.

## Notes and dead ends

- Evidence is thin: description and solved-state metadata plus the range-wide route map for
  `delivery.keplerops.test:8443`. The technique is **reconstructed** from the challenge
  wording ("framing capability", "protected package action", "restricted assessment") and
  the documented inspection lifecycle; commands are templates.
- A package that satisfies the interface but performs no privileged action is a dead end:
  scoring depends on the *assessment* being returned, so the frame must select the protected
  action, not merely a valid connector shape.
- Do not confuse this with the support-side diagnostics upload
  (`/api/diagnostics/{job}/package`); that validates `expected_output` and belongs to the
  diagnostics chain, not the delivery inspector.
