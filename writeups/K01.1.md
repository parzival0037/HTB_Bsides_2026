# K01.1 — The developer left a way back

> **Category:** 2. KeplerOps · **Points:** 50 · **Difficulty:** easy
> **Solved by:** team agent

## Where this happens

![Range map — three segments, hosts and services](../docs/img/segments.png)

Primary service for this card: `source.keplerops.test`. The map shows which segment it sits in and how

## At a glance

| | |
|---|---|
| **Vulnerability / bug class** | Stale credential material on an endpoint — a long-lived personal access token in plaintext, reused across three services |
| **Tools** | shell (`find`, `grep`), `git`, `curl` against the Gitea API |
| **Attack surface** | `rowan-dev` (10.77.50.20, SSH `:2222`); `https://source.keplerops.test` |
| **Prerequisite** | A session on the developer workstation — chapter 1 hands you the box |
| **Flag** | accepted, value not recorded |

**What you are about to read:** how a workstation's convenience settings become an entry
point for the whole range. The bug class is credential hygiene: `fk_developer_…` sits in a
config file, was never rotated, and is accepted by the source host, the CI and the report
service at once. No cryptography is broken — the token simply still works.

## Objective

Chapter 1 is framed as *the workstation is yours*. K01.1 asks for the first hop off it:

> Recover the developer's usable repository access (git credentials/tokens on the
> workstation) and retrieve the current project handover from the FieldKest repositories.

The deliverable is therefore **repository access as the developer** plus one document —
the project handover — that the rest of chapter 1 depends on.

## Background you need

- **Workstations are credential stores.** So git never prompts, developers keep tokens in
  files: `~/.git-credentials`, an `insteadOf` URL with `user:token@`, `~/.netrc`, `~/.npmrc`.
- **A PAT is a bearer secret.** Whoever holds the string is the developer to the API: no
  second factor, no source binding. A token leak equals API takeover without the password.
- **The handover document is the intended prize**, not a flag file. It names systems,
  the release train and open work items, and it is what a real intruder reads first.

`rowan-dev` is reachable only through the supervised SOCKS pivot; its SSH daemon is limited
(`AllowTcpForwarding local`, `PermitOpen 127.0.0.1:13389`), so it is a jump box, not a
routing host.

## Walkthrough

### 1. Reach the source host

```bash
curl -sS --socks5-hostname 127.0.0.1:1080 -k https://source.keplerops.test/
```

The Gitea front end answers. A bare `git clone` from the range box fails — the box cannot
route to `10.77.x` — which is where people lose the most time.

### 2. Find the credentials left behind (reconstructed)

The lane that solved this card left no command trail, but the range notes confirm the
outcome: git, Jenkins and the report service all accept **one** token,
`rowan.ito:fk_developer_…`, and the npm entry is that same token base64-wrapped.

```bash
# illustrative template, not a captured transcript
grep -rIl --exclude-dir=.cache -e 'fk_developer' -e 'fk_support' ~ 2>/dev/null
ls -la ~/.git-credentials ~/.netrc ~/.npmrc ~/.config/fieldlink/ 2>/dev/null
```

The useful hits are `user:token@host` in git's credential file, the same pair base64'd in
`~/.npmrc` (`//packages.keplerops.test/:_auth`), and per-service bearers in
`~/.config/fieldlink/`. None of them needs a password.

### 3. Become the developer on the API

```bash
# illustrative template; the contents route is the documented one
curl -sS -k -u 'rowan.ito:fk_developer_…' https://source.keplerops.test/api/v1/user/repos
curl -sS -k -u 'rowan.ito:fk_developer_…' \
  'https://source.keplerops.test/api/v1/repos/fieldkest/fieldlink-connector/contents/?ref=main'
```

No password reuse, no guessing: the token authenticates directly, and the resulting
requests are *authorised*, so they look like normal developer traffic.

### 4. Getting the flag

The accepted answer is the value carried by the **project handover** in the FieldKest
repositories, read with the developer's stolen access. The exact document and field were
not preserved in the lane notes, so the value is not reproduced here.

## Why this works (the vulnerability explained)

The failure is credential lifetime and blast radius, not a missing check. Three properties
combine into a back door: it is a **bearer secret** (reading a file is enough — no device
binding, no mTLS), it has an **unbounded lifetime** (tokens minted for a one-off clone
keep authenticating for months), and it is **shared and over-scoped** (one token opens
the source host, Jenkins and the report service, so one file leak yields three footholds).

A correct setup uses short-lived, per-service, least-privilege tokens stored in an agent
or keyring rather than a plaintext file. Because tokens are *identifiable* they are also
auditable: log the token ID per request and alert when one token is used from two source
hosts, or from a host that is not an approved runner.

## Detection and fix

- **Log signal:** one PAT ID hitting the git and CI APIs inside a short window; clones of
  repositories the role does not normally open; non-git user agents on the API.
- **Fix:** rotate every credential found on the box; move secrets into a keyring/agent;
  issue per-service tokens with narrow scope and short TTL; fail the image build when
  `~/.git-credentials` or an inline `user:token@` remote exists; review the audit log.
- **Posture:** treat the workstation as untrusted infrastructure — it will be stolen,
  imaged or compromised, so plan for it instead of trusting it.
