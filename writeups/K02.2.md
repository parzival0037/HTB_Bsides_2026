# K02.2 — An input outside its lane

> **Category:** 2. KeplerOps · **Points:** 50 · **Difficulty:** easy
> **Solved by:** pi lane K02

## At a glance

| | |
|---|---|
| **Vulnerability / bug class** | Leak through build artifacts — a retained review note exposes a token the job was never meant to publish |
| **Tools** | `curl` (Jenkins API, review worker API), `jq`, `unzip` |
| **Attack surface** | `https://ci.keplerops.test/job/fieldlink-report/1842/artifact/reports/REVNOTE-1842.json`, the workspace zip, `https://review.keplerops.test/api/runs/BLD-1842/artifacts/...` |
| **Prerequisite** | `rowan.ito` developer credentials; build number `1842` from K02.1 |
| **Flag** | accepted, value not recorded |

**What you are about to read:** how a failed build publishes more than its log. Jenkins archives
whatever the job declares, so a review note meant for a *different* consumer is downloadable
beside the console — and it carries both a token and the contract for a corrected provider.

## Objective

> The report build failed, but it retained a review note separate from the console log. Recover
> that note and establish the input contract for submitting a corrected report provider.

Two outputs: the note (value in `review_token`) and the *contract* — schema, entry point and the
byte-level rules the review consumer enforces. The contract is the real deliverable; without it
the next card's `provider.zip` is rejected.

## Background you need

- **Jenkins archives artifacts, not just logs.** `archiveArtifacts` copies files into the build
  record, readable by anyone with job read access — often wider than the original audience.
- **The workspace zip is a second copy**, so a file can leak even when it was *not* declared.
- **Review notes are interface documents**: schema, digest binding, immutable fields.

## Walkthrough

### 1. Enumerate what the build kept

```bash
curl -sS -u 'rowan.ito:fk_developer_…' \
  https://ci.keplerops.test/job/fieldlink-report/1842/api/json \
  | jq '{result, artifacts: [.artifacts[].relativePath]}'
```


`result` is `FAILURE` yet `artifacts` is non-empty: the note is listed even though the report step
died. That is the "separate from the console log" half of the challenge.

### 2. Fetch the review note

```bash
curl -sS -u 'rowan.ito:fk_developer_…' \
  https://ci.keplerops.test/job/fieldlink-report/1842/artifact/reports/REVNOTE-1842.json \
  | tee /tmp/REVNOTE-1842.json | jq .
```

The note is small JSON: `review_token` holds the value, the other fields are the input contract.

### 3. Cross-check the reviewer's copy

```bash
curl -sS -u 'rowan.ito:fk_developer_…' \
  https://review.keplerops.test/api/runs/BLD-1842/artifacts/REVNOTE-1842.json | jq .
```

The worker stores the same note under the build's run id: a real interface artifact. If the
artifact route were pruned, the file is inside the job's workspace zip
(`artifact/*zip*/workspace.zip`) — list it with `unzip -l` first.

### 4. Read the contract, not just the token

The note plus the review worker's client reference
(`https://review.keplerops.test/.well-known/fieldkest-client`) define what a corrected provider
must look like: schema `fieldkest.report/v2`; entry point `provider.py` exporting
`render_report`; immutable and mutable assessment fields kept distinct; binding by the exact-byte
digest of the K02.1 baseline fixture; delivery as `provider.zip` to the `fieldlink-report-review`
job.

The digest rule is the one that bites: validation is against the fixture's *bytes*, so a
re-serialised fixture fails even when the JSON is identical — hence K02.1's raw-blob restore.

### 5. Getting the flag

The accepted answer is the note's `review_token`, recovered from the retained
`reports/REVNOTE-1842.json`. Accepted; the value is not reproduced here.

## Why this works (the vulnerability explained)

The bug is a mismatch between *who the data was for* and *who can reach it*. The note is produced
for the review worker; Jenkins publishes it under the build, where the audience is "anyone who
can read the job". Nothing re-applies the note's classification when it becomes an artifact and
nothing strips the token before archiving. This is the "output lane" of a data-flow bug: pipelines
validate inputs and forget that outputs are data with a destination. Every artifact is a
publication decision — `archiveArtifacts **/*` publishes debug dumps, env files and review notes.

The second lesson is *contracts as attack surface*. The note is worth more than the token it
embeds: it describes the validator (schema, entry point, immutable fields, digest binding), and
anyone who can read the interface can satisfy it exactly — which is what the next card does.

## Detection and fix

- **Log signal:** artifacts with credential-ish names (`*token*`, `*note*`, `env*`) in build
  records; artifact downloads from outside the owning team.
- **Fix:** archive an explicit allow-list instead of `**/*`; keep tokens out of the workspace or
  scrub them before archiving; restrict job read access; expire build records.

## Notes and dead ends

- **Evidence is solid**: lane K02 recorded the artifact path, the workspace copy, the worker copy
  and the `review_token` field; the `curl` calls above follow those routes.
- `review.keplerops.test/api/jobs` is a different interface from `/api/runs/.../artifacts`: the
  job API is what the reviewer *creates*, not what this card needs.
- The note is not in the console: K02.1's console ends with the *other* card's value, so reading
  only `consoleText` yields the wrong flag. The brief's "separate from the console log" is the
  hint.
- Do not submit the schema as the answer: the contract is prose for the next card, the accepted
  value is the token in the note.
- The workspace zip is large: `unzip -l`, then extract one path.
