**What you are about to read:** how a courier handover was "emptied" in a blank-template
commit, why that left the real text in the object database, and how `git show
<commit>:<path>` prints it. The lesson carries over to every `.git` directory you meet.

## Objective

> Recover the content the desk no longer serves at its current path.

The desk publishes a courier handover for delivery `DL-204`. The copy you can read today is
a template: the headings survive, the notes are gone. The card is to reconstruct the real
handover — and the value recorded in it — from what the repository still carries.

## Background you need

- **Git is content-addressed and append-mostly.** A commit is a snapshot; blanking a file
  creates a *new* snapshot. The old blob stays reachable from every commit on every branch.
- **The working tree is not the repository.** A web-served checkout shows one branch tip;
  history (`git log --all`) is a second, usually anonymous, surface.
- **`commit:path` addressing.** `git show <sha>:<path>` prints the exact bytes at that
  revision — no checkout, no merge, no state change.
- **Why authors do it on purpose:** credentials "removed" in a cleanup commit, customer data
  deleted before publishing.

## Walkthrough

### 1. Recon — the desk offers its own repository

The `:8080` front page is a markdown index and the range map describes that port as
"markdown index, `git/handover.git`". Cloning costs one request and no credential:

```bash
git clone http://workbench.training:8080/git/handover.git /tmp/handover
# Cloning into '/tmp/handover'...
```

The checkout contains a single file, `handover.md` — a stub with headings and no notes.

### 2. Finding the flaw — the log proves a real copy existed

```bash
cd /tmp/handover && git log --all --oneline --decorate --stat
```

```
a01d629 (HEAD -> main, origin/main, origin/HEAD) leave blank handover template
 handover.md | 8 +++-----
 1 file changed, 3 insertions(+), 5 deletions(-)
04176f3 record courier handover
 handover.md | 9 +++++++++
 1 file changed, 9 insertions(+)
```

Read the diff shape before the content: `04176f3` added nine lines, `a01d629` replaced them
with three. On `HEAD` the notes are gone; in the object database the nine lines remain, one
hop back. Confirm the blob is reachable rather than dangling:

```bash
git rev-list --all | wc -l        # 2 — both commits are on main
git cat-file -t 04176f3:handover.md
# blob
```

### 3. Exploitation — print the old blob

```bash
git show 04176f3:handover.md > /tmp/handover-04176f3.md
diff -u /tmp/handover-04176f3.md /tmp/handover/handover.md    # the removed lines
```

That output is the file exactly as committed, notes included. The recovered text also names
the next hop of the desk: finish the rehearsal from the dispatch workbench — which is what
`T01.2`/`T01.3` work on. Nothing was checked out, so `HEAD` was never touched.

### 4. Getting the flag

The value was part of the content the blank-template commit removed, so it appears in the
`git show` output above. The desk's flag registry attributes the accepted value to `git
history 04176f3:handover.md`; the value itself was not transcribed into this write-up.

## Why this works (the vulnerability explained)

Two mistakes line up. First, **the publisher treats the working tree as the unit of
publication** — a branch tip is not a redacted document when every historical revision of
that path is still cloneable. Second, **the "removal" is just another commit**: blanking a
file changes the present, not the past. Git has no concept of forgetting; only rewriting
history (`git filter-repo`, fresh repo) drops a blob, and caches and CI artifacts survive
even that. The general rule: **anything committed is published the moment the repository is
readable.**

## Detection and fix

- **Detection:** a `git-upload-pack` / `info/refs` request on `/git/<repo>.git` from an
  unexpected source, or a clone by a client that never browses the desk.
- **Fix:** do not serve internal repositories from the desk; publish a generated export, not
  the repo. Rotate anything that was ever committed — a rewrite is cleanup, not remediation.
  Gate exposure with `gitleaks --log-opts=--all` or `trufflehog git file://…`.
