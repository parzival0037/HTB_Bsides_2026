**What you are about to read:** how a browser closed days ago still contains the
half-written support ticket you need. The bug class is *residual state*: session restore and
form history are durability features, and they keep exactly the data an application would
never show you — draft bodies, unsent text, internal URLs — in a file the user can read.

## Objective

> Recover the unfinished ARWC support ticket retained by the closed browser.

The brief names the artifact family itself: session restore, form history, `places.sqlite`,
`logins.json`, `recovery.jsonlz4`. The ticket is the ARWC maintenance thread that returns
later in the range (`SUP-2841`, "ARWC connector callback latency", with `ESC-2841` and
`REV-2841` as siblings).

## Background you need

- **Session restore is a live-state snapshot.** Firefox rewrites
  `sessionstore-backups/recovery.jsonlz4` every few seconds, keeps `previous.jsonlz4` beside
  it, and erases neither on close — crash survival is the point.
- **mozLz4 is not `.lz4`.** The blob is the magic `mozLz40\0`, a 4-byte length, then a raw
  LZ4 **block**. `lz4 -d` rejects it; `lz4.block.decompress(blob[8:])` works.
- **The session JSON holds more than URLs.** Each tab entry has `url`, `title` and `formdata`
  with the field values *as typed*, including text never submitted.

## Walkthrough

### 1. See what survived

```bash
ls -la ~/.mozilla/firefox/*/ ~/.mozilla/firefox/*/sessionstore-backups/
```

One profile, with `recovery.jsonlz4` and `previous.jsonlz4` present and days old — the
browser has not run since, so nothing rotated the snapshot away.

### 2. Decompress the snapshot (illustrative template)

```python
# illustrative template, not a captured transcript
import json, lz4.block, pathlib
p = pathlib.Path.home()/".mozilla/firefox/<profile>/sessionstore-backups/recovery.jsonlz4"
assert p.read_bytes()[:8] == b"mozLz40\0"
session = json.loads(lz4.block.decompress(p.read_bytes()[8:]))
for win in session.get("windows", []):
    for tab in win.get("tabs", []):
        for e in tab.get("entries", []):
            print(e.get("url"), "|", e.get("title"), json.dumps(e.get("formdata", {})))
```

### 3. Read what the URL list will not tell you

The hit is the internal support board (`https://support.keplerops.test/scp/`, the osTicket
instance from the range map) on the ARWC connector ticket. Its `formdata` still carries the
draft reply: symptom, connector version, and the question the engineer meant to ask the
customer.

```bash
# illustrative template
sqlite3 ~/.mozilla/firefox/<profile>/formhistory.sqlite \
  "select fieldname, value from moz_formhistory order by lastUsed desc limit 40;"
sqlite3 ~/.mozilla/firefox/<profile>/places.sqlite \
  "select url, title from moz_places where url like '%support%';"
```

`formhistory` recovers short fields the session JSON drops; `places` proves which pages were
opened rather than typed. `logins.json` is weakest — its fields are encrypted with keys in
`key4.db`, so alone it yields metadata, not secrets.

### 4. Getting the flag

The accepted answer is the value carried by the recovered unfinished ticket — the draft
abandoned when the tab was closed. It was submitted and accepted; the exact field was not
preserved in the lane notes, so the value is not reproduced here.

## Why this works (the vulnerability explained)

Everything here is a feature: crash-safe restore, autocomplete, visit history — each spares
the user work and persists data the application layer believed was discarded. The security
failure is a scope assumption. The portal treats a draft as private because it was never
submitted and sits behind a session cookie. The workstation keeps a copy in a per-user file
that survives logout and reboot: authorisation stops at the browser boundary, the *data*
does not. Anything typed on a shared host is already disclosed — a draft is not secret,
only unpublished.

The fix is not "hide the file" (the feature needs it readable) but to stop leaving
high-value drafts on multi-user hosts: full-disk encryption, profile purge on logoff,
session restore and form history disabled by policy, `key4.db` under a primary password, and
a server-side draft that requires authentication.

## Detection and fix

- **Log signal:** host-side — a process other than Firefox opening `recovery.jsonlz4`,
  `formhistory.sqlite` or `key4.db`.
- **Fix:** disable session restore and form history on shared images, purge profiles at
  logoff, encrypt the disk, and keep drafts out of the browser.

## Notes and dead ends

- **Evidence is thin; this walkthrough is reconstructed.** K01.2 was solved by the team
  agent and only the challenge brief survived. The artifact names come from that brief; the
  commands are illustrative because no transcript exists — none is invented.
- `lz4 -d recovery.jsonlz4` fails: the file is raw mozLz4, not the framed format. Strip the
  header and call `lz4.block.decompress`.
- Copy the profile after Firefox exits — the snapshot is rewritten continuously, so a live
  copy can yield truncated JSON; `previous.jsonlz4` is the fallback.
