# Retained policy compiler migration

Release Engineering retained `fieldkest-policyc` 2.6.4 while the policy
service moves its exception rules to the current compiler. The binary, link
map, fixed corpus, and four named policy fragments are the migration inputs.
Do not rebuild the retained binary: acceptance records bind its bytes and
embedded program.

The binary runs on Linux x86-64:

```
bin/fieldkest-policyc examples/rejected-incomplete.env
```

Its embedded table begins with `FKPC`. The little-endian header is twelve
bytes: magic, `u32` program offset relative to the header, `u16` instruction
count, and `u16` instruction width. Instructions are four bytes: opcode,
flags, and a little-endian `u16` operand.

`corpus/policy-corpus-2026-09-r4.json` contains the immutable compatibility cases.
Channel and tenant class are required input context but are deliberately not
policy conditions in this revision; an accepted result must show which fields
the compiler actually evaluated.

## Fragments

The policy is decomposed into four named fragments, each evaluating one
condition independently. Assemble each as a minimal FKPC program that tests
its stated condition and terminates with RETURN. Use the same encoding as the
retained binary's embedded program table: one instruction per four bytes, with
opcode (1), flags (1, always 0), and operand (2, little-endian).

| Fragment              | Condition evaluated                             | Program ID                            |
|-----------------------|-------------------------------------------------|---------------------------------------|
| tenant-state          | tenant_state is a member of set index 0         | FKPC-FRAGMENT-TENANT-STATE            |
| connector-version     | connector_api >= constant index 0 (semver)      | FKPC-FRAGMENT-CONNECTOR-VERSION       |
| signer-lineage        | signer_lineage is a member of set index 1       | FKPC-FRAGMENT-SIGNER-LINEAGE          |
| compatibility-exception | compatibility_exception equals constant index 1 | FKPC-FRAGMENT-COMPATIBILITY-EXCEPTION |

The source service validates each assembled fragment by running it against
server-side cases covering accepted and rejected inputs. A correctly assembled
fragment passes all validation cases. Submit with operation `fragment-check`
and `policy_input={"fragment_id": "<name>"}`.

## Service

The source service accepts migration checks at
`POST https://source-tools.keplerops.test:8443/api/policy-compilers/fieldkest-policyc/evaluations`.
Use the saved developer credential and workstation CA. The request shapes are
in `api/`. Fragment imports use operation `fragment-check`; the complete model
uses `corpus-check`. Create a fresh one-use acceptance nonce with
`POST /api/policy-compilers/fieldkest-policyc/nonces` before operation `accept`.

Each response includes a request ID and a service-owned receipt. An acceptance
request must include the fixed corpus result digest, `cf60e746abf133754466b724318419da127e1c7cb3ee74f48ae432cfd74e601a`, and a
policy input containing every field in the corpus. Nonces expire after five
minutes and are consumed by the first syntactically valid acceptance request.
